# 仕様書サイトマップシートの構築

## このスキルが解く問題

提案の見積が崩れるのは、たいてい「ページ数を数え間違えた」からではない。
**制作範囲・工程・CMS化範囲がページ単位で確定していない**まま金額を出すからだ。

サイトマップを樹形図で描いても、そこからは見積が出ない。
必要なのは、1ページ＝1行で、どの工程が発生し、公開後に誰が更新するかまでを
横に並べた表。このスキルはその1枚を組み立てるための道具一式を提供する。

**Excelである理由**：見積の下地だから。単価列を横に足せばそのまま金額になり、
制作着手後は進捗管理表として使い回せる。HTMLワイヤーは合意形成用で、役割が違う。

## ワークフロー

### STEP 1. 現行サイトを棚卸しする

**推測でページ数を数えない。** 実測しないと移行工数を外す。
手順は `references/audit.md` に詳しい。最低限これだけは取る。

| 取るもの | 手段 |
|---|---|
| 全URLと件数 | `sitemap.xml` を取得して第1階層別に集計 |
| 投稿・カテゴリの内訳 | カスタム投稿タイプ・タクソノミごとの件数 |
| ページ別の実力 | GA4のページビュー・セッション・CV |
| 検索での実力 | Semrushの自然検索キーワードと流入 |
| 技術構成 | CMS・テーマ・フォームの実装方式・総容量 |

棚卸しの結果は備考欄の根拠になる。**「なぜこのページなのか」が数字で追える状態**に
しておくと、先方から質問が来たときにシート1枚で答えられる。

### STEP 2. 論理構造を確定する

第1〜第4階層とURLを決める。決めるときの原則：

- **第1階層は6項目以内。** 超えたら情報設計を疑う
- **詳細ページ（商品・記事）は親を持たせずフラットに置く。** 1つの商品が複数
  カテゴリに属する以上、URLに親を入れると重複URLを作るか、無理に1つへ押し込む
  ことになる。タクソノミとパンくずで紐づける
- **絞り込みだけのページは実体ページにしない。** noindexにして行だけ残す
- **今回触らないページも行に残す。** 「対象外」と明示されていないと、
  後から「これも入っていると思った」になる

### STEP 3. 工程マークを付ける

構成・デザイン・コーディングの各列に、発生する工程だけ `■` を入れる。
**付けない列があることが情報になる。** 全部に付けると見積が読めない。

判断に迷ったら `references/columns.md` の「工程マークの付け方」を読む。

### STEP 4. 更新性を判定する

◎○△× の4段階。**これがCMS化の範囲を決める。**

| 記号 | 意味 | コーディングのWP列 |
|---|---|---|
| ◎ | 公開後に頻繁に更新 | ■（必須） |
| ○ | 年数回の更新 | ■ |
| △ | ほぼ更新しない | 原則なし |
| × | 更新しない | なし |

**◎○ の行数がWordPress化の工数**になる。ここが曖昧なまま見積を出すと、
公開後に「更新できない」と言われて追加改修が発生する。

### STEP 5. 付帯ブロックを書く

シート下部に3ブロックを置く。省略すると後で必ず揉める。

| ブロック | 書くこと |
|---|---|
| 制作対象外 | 据え置くページと、その結果どうなるか（例：旧デザインのまま残る） |
| URL移行 | 旧URL→新URL。件数を明記し、301の総数を書く |
| 要確認事項 | 先方に決めてもらう項目。工数の変数になるものを先頭に |

### STEP 6. 生成して検証する

```bash
# 作業ルート（AGENTS.md がある階層）から実行する
OUT="仕様書_{クライアント名}_提案サイトマップ.xlsx"
SPEC=skills/gg-sitemap-spec/scripts
python $SPEC/build_sitemap_xlsx.py spec.json -o "$OUT"
python "$(python scripts/find-skill-script.py xlsx scripts/recalc.py)" "$OUT"   # 数式のキャッシュ値を埋める
python $SPEC/verify_sitemap_xlsx.py "$OUT"                                     # 品質チェックリストを自動判定
```

`recalc.py` が `errors_found` を返す状態、または `verify` が `FAIL` を出す状態で渡さない。
`WARN` は誤りとは限らない。指摘された行を見て、意図どおりならそのまま進めてよい。

自動判定できない項目（備考の中身が根拠になっているか、対象外の結果が書いてあるか）は、
下の品質チェックリストで目視確認する。

## シート仕様（列構成の正本）

```
┌─ 論理構造 ─────────────┬─ 見積 ──────────────────────────┬─────┬──────┐
│ ID │第1│第2│第3│第4│URL │ 構成      │ デザイン    │ コーディング     │更新性│備考  │
│    │層 │層 │層 │層 │    │TOP SP 下A 下B│TOP SP 下層 ﾌｫｰﾏｯﾄ│TOP SP 下A 下B WP ﾌｫｰﾑ│      │・根拠│
└────┴───┴───┴───┴───┴────┴──────────┴────────────┴──────────────────┴─────┴──────┘
```

- A列 ID ／ B〜E列 第1〜第4階層 ／ F列 URL
- G〜J列 構成 ／ K〜N列 デザイン ／ O〜T列 コーディング
- U列 更新性 ／ V列 備考・根拠
- ヘッダーは3段（大分類／中分類／小分類）。`freeze_panes` は `G7`

**下層A／下層B は単価区分。** 会社の単価表に合わせて列名を差し替えてよい。
差し替えたら凡例も直す。列を増減する場合は `columns` を編集する。

最下部に工程別の `COUNTIF` 集計行を必ず置く。
**単価を横に掛ければそのまま見積になる**のがこのシートの存在理由。

## 記入の原則

**ページ数ではなくテンプレート数で考える。** 制作費を決めるのはテンプレート数と
移行件数であって、ページ数ではない。同じ型のページは2枚目以降がほぼ流用になる。
テンプレート構成を別途整理し、備考欄にどのテンプレートを使うか書く。

**備考欄に根拠を書く。** 「3ヶ月18,095セッション・来店予約0件」のように、
実測値を入れる。形容詞（重要な、効果的な）ではなく数字と固有名詞を使う。

**移行件数を件数で見積もらない。** WordPress上でのテーマ刷新なら、商品249件は
「移行」ではなくパーマリンクとタクソノミの付け替えで、一括処理できる。
件数×単価で積むと実態より高くなる。作業単位で積む。

**数字には出所を書く。** GA4実測／Semrush推計／ヒアリング／仮置き のどれか。
出所が言えない数字はシートに載せない。

## 品質チェックリスト

提出前に全項目を確認する。

- [ ] 第1階層が6項目以内に収まっている
- [ ] すべての行にURLが入っている（`{slug}` のような変数表記も可）
- [ ] 工程マークが空の列がある（全部に `■` が付いていない）
- [ ] 更新性が全行に入っている
- [ ] 更新性◎○の行に更新手段がある（WP列の `■`、またはTOP/下層のコーディングに
      含まれることが備考で分かる）
- [ ] 集計行のCOUNTIFが動いている（`recalc.py` が success）
- [ ] 備考欄に実測値の根拠が入っている行が半数以上ある
- [ ] 「制作対象外」ブロックに、据え置いた結果どうなるかが書いてある
- [ ] 「URL移行」ブロックに301の総件数が書いてある
- [ ] 「要確認事項」の先頭が、工数の最大の変数になっている
- [ ] 凡例が列名と一致している（列名を差し替えたら凡例も直す）
- [ ] クライアント名・案件名が正しい（他案件の固有名詞が残っていない）

---

## やってはいけないこと

- **推測でページ数を数える**（sitemap.xmlを取れば実測できる）
- **全列に `■` を付ける**（見積が読めなくなる）
- 更新性を空欄のまま出す（CMS化範囲が決まらず、公開後に追加改修になる）
- 対象外ページを行から消す（「入っていると思った」の原因になる）
- URL移行ブロックを省略する（公開直後に自然検索が落ちる）
- 備考欄を形容詞で埋める（「重要なページ」では判断できない）
- 金額をこのシートに書く（見積書の役割。ここは数量まで）
- 他案件のクライアント名や固有名詞を残したまま提出する

## 併用するスキル

| 作りたいもの | 使うスキル |
|---|---|
| クライアント向けクリッカブルワイヤー | `gg-wireframe` |
| 提案の判断基準・レビュー | `gg-proposal-standard` |
| 費用シミュレーター等の動く資料 | `gg-proposal-artifact` |
| 提案書（PPTX） | `pptx` |
| このシートの生成・検証 | `xlsx`（`recalc.py` を使う） |

このスキルは**数量と範囲**を確定させる。金額は見積書側、構成の合意はワイヤー側。
役割を混ぜない。
