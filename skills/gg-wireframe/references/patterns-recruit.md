# 採用サイト ページ構成パターン

## 1. 前提となる設計思想

採用サイトはコーポレートサイトの縮小版ではない。求職者の意思決定は
**「知る → 自分に重ねる → 不安を消す → 応募する」**の4段階で進み、
サイトの役割は主に第2〜3段階にある。第1段階（認知）はナビ媒体や
Indeed／求人検索エンジンが担い、第4段階は応募フォームが担う。

つまり採用サイトの勝負どころは**「自分に重ねられるか」と「不安が消えるか」**。
ここに割くページ量が足りない構成は、どれだけ見た目が良くても機能しない。

**閲覧はスマートフォンが主。** 新卒はほぼ全数がSPで初回接触する。
ワイヤーは必ずSP表示で先にレビューし、PCは後から確認する順序にする。

## 2. サイトマップの型

| 階層 | ページ | 担う段階 | 提案での優先度 |
|---|---|---|---|
| 1 | TOP | 全体 | 必須 |
| 2 | 採用メッセージ／求める人物像 | 知る | 必須 |
| 2 | 数字で見る◯◯ | 重ねる・不安 | 必須 |
| 2 | 会社を知る（事業紹介） | 知る | 必須 |
| 2 | 仕事を知る（職種一覧） | 重ねる | 必須 |
| 3 | 職種詳細 | 重ねる | 必須 |
| 2 | 人を知る（社員一覧） | 重ねる | 必須 |
| 3 | 社員インタビュー詳細 | 重ねる | 必須 |
| 3 | 1日の流れ／座談会 | 重ねる | 推奨 |
| 2 | 環境・制度（福利厚生／研修／キャリアパス） | 不安 | 必須 |
| 2 | 募集要項（新卒／キャリア） | 応募 | 必須 |
| 2 | 選考フロー | 不安 | 必須 |
| 2 | FAQ | 不安 | 必須 |
| 2 | エントリー／完了 | 応募 | 必須 |
| 2 | 説明会・イベント情報 | 応募 | 新卒案件では必須 |
| 2 | 社員インタビューのタグ一覧 | 重ねる | 推奨（竹以上） |

**新卒とキャリアの分離**
両方を1サイトで扱う場合、TOPで早い段階に入口を分岐させる。
募集要項・選考フロー・FAQは必ず別ページか別タブにする。
「新卒とキャリアで異なる情報が同一ページに混在」は離脱の主因になる。

## 3. TOPページの標準構成

| # | ブロック | 目的 | 外せない要素 |
|---|---|---|---|
| 1 | ヘッダー（追従） | 常時エントリー導線 | ロゴ／ナビ／エントリーボタン |
| 2 | ヒーロー | 採用コンセプトの提示 | 大型コピー＋キービジュアル |
| 3 | 新卒／キャリア分岐 | 振り分け | 2カード（該当案件のみ） |
| 4 | 3つの特長 | 端的な魅力提示 | アイコン＋見出し＋根拠 |
| 5 | 数字で見る | 客観的な安心 | 4〜8指標 |
| 6 | 仕事を知る | 職種の広がり | 職種カード＋一覧リンク |
| 7 | 人を知る | 自分事化 | 社員カード3〜4名＋一覧リンク |
| 8 | 環境・制度 | 不安の解消 | 制度アイコン＋詳細リンク |
| 9 | 会社を知る | 事業理解 | 事業概要＋コーポレートサイトリンク |
| 10 | 募集要項・選考フロー | 応募直前情報 | 募集職種リスト＋STEP |
| 11 | FAQ | 最後の不安 | 3〜5問＋一覧リンク |
| 12 | エントリーCTA | 刈り取り | エントリー＋説明会予約 |
| 13 | フッター | — | コーポレートサイトへの相互リンク |
| 14 | SP固定CTA | SP主体への対応 | エントリー／説明会の2分割 |

**採用サイトのトーンはコーポレートと揃えなくてよい**
BtoB企業でも、採用サイトだけ大胆なトーンにする例は近年一般的。
ワイヤーは無彩色なのでトーンの議論を持ち込まずに構成だけ合意でき、
「デザインの方向性は次のフェーズで2〜3案」と整理できる。これは提案上の強み。

## 4. 職種詳細ページの標準構成

1. 職種名＋一言定義
2. 仕事内容（3〜5項目）
3. 1日のスケジュール（タイムライン）
4. やりがい／大変なこと ※両方書く
5. 必要なスキル・向いている人
6. キャリアパス（1年目→3年目→5年目）
7. この職種の社員インタビューへの導線
8. 募集要項へのリンク／エントリーCTA

**「大変なこと」を書く価値**：入社後ギャップは早期離職の主因であり、
先に開示するほど応募の質が上がる。提案時に「あえて書く」設計を出すと、
他社と明確に差がつく論点になる。

## 5. 社員インタビュー詳細の標準構成

1. 顔写真（縦）＋氏名／所属／入社年
2. 本人の言葉を抜いた大見出し
3. Q&A 4〜6問（入社理由／現在の仕事／印象的な出来事／今後）
4. 1日のスケジュール
5. 学生・求職者へのメッセージ
6. 他の社員へのリンク（3名）
7. エントリーCTA

**一覧ページには必ず絞り込み軸を置く**：職種／入社年次／キャリア区分／勤務地。
求職者は「自分に近い人」を探しに来るので、軸がないと重ねられない。

## 6. 募集要項ページ

定義テーブルで統一。全職種で行ラベルを揃える。

| 行 | 備考 |
|---|---|
| 職種 | — |
| 雇用形態 | — |
| 応募資格 | 新卒は卒業年度、キャリアは経験年数 |
| 勤務地 | 転勤有無を必ず明記 |
| 勤務時間 | フレックス・裁量労働の有無 |
| 給与 | 新卒は初任給、キャリアはレンジ |
| 諸手当 | — |
| 昇給・賞与 | — |
| 休日休暇 | 年間休日日数を数字で |
| 福利厚生 | — |
| 試用期間 | — |
| 選考フロー | STEPへのリンク |

求人票と表記がずれると信頼を損なう。ワイヤーの注釈に
「求人媒体・ハローワーク求人票との表記統一が必要」と要確認事項として書く。

## 7. 求人検索エンジン連携（提案での差別化ポイント）

募集要項ページに JobPosting 構造化データを実装すると、
Googleしごと検索やIndeedへ自動的に情報が載る。
これはワイヤー上は見えないが、募集要項ページの注釈に必ず書く。
「デザインだけでなく集客構造まで設計している」という証明になる。

注釈例：
> **差別化** 本ページに JobPosting 構造化データを実装。Googleしごと検索・Indeedへ
> 自動連携され、媒体費をかけずに露出を確保する。掲載項目は上表と1対1で対応。

## 8. よくある現行採用サイトの欠陥と打ち手

| 症状 | ワイヤーでの打ち手 |
|---|---|
| コーポレートサイトの1ページに採用情報が同居 | 独立サイト化し、相互リンクを設計 |
| 社員インタビューが2〜3名で更新が止まっている | 一覧＋絞り込み構造にし、CMSで追加できる設計を注釈で明示 |
| 数字がすべて画像で作られていて更新できない | 数字ブロックをCMS化。テキスト化でSEOにも効く |
| 募集要項が採用媒体へのリンクだけ | 自社サイト内に要項ページを持ち、構造化データを実装 |
| 良い情報しか載っていない | 残業時間・離職率など不利な数字を1つ入れる設計を提案 |
| 新卒とキャリアが混在 | TOPで分岐、要項・フロー・FAQを分離 |
| SPでエントリーボタンが探せない | SP固定CTAを設置 |
| 選考フローが書かれておらず応募が怖い | STEP表示＋各段階の所要期間を明記 |
