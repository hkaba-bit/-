# レビュー手順

提案を評価・添削するときに読む。

## 手順

1. 与件（案件情報・議事録・RFP）を先に読み、決裁フローと勝ち筋を把握する
2. 提案を読む
3. 評価優先順位の1〜6の順に照合する
4. 各指摘を P0 / P1 / P2 に分類する
5. 「該当箇所 → 何が問題 → どう直すか」の順で書く

## 分類

| 優先度 | 観点 |
|---|---|
| P0 | RFP・先方要望で名指しされた項目への回答漏れ |
| P0 | 数字の出所不明、根拠なき効果予測、税別税込の欠落 |
| P0 | 事実誤認（社名・製品名・現状認識の誤り） |
| P1 | 論点がぶれている、勝ち筋が不明瞭 |
| P1 | 具体性の不足（誰が何をいつやるか不明） |
| P1 | 決裁者が承認できる材料の欠落 |
| P2 | 表現・構成・見た目の改善提案 |

**P0 が1件でもあれば「提出不可」と明記する。**

## 出力フォーマット

```markdown
### {案件名} レビュー @ {日付}

| 優先度 | 箇所 | 指摘 | 対応 |
|---|---|---|---|
| P0 | p.8 効果予測 | 「CVR2倍」の出所がない → 自社実績のレンジに置き換えるか削除 | [ ] 未対応 |

**P0 が n件あるため提出不可。**
```

## 書いた本人が見落としやすい点

ここを重点的に見る。

| 見落とし | 確認方法 |
|---|---|
| 決裁者が理解できない専門用語 | マーケ知識ゼロの人が読んで意味が通るか |
| 「伴走します」の中身が空 | 誰が何を何回やるか書いてあるか |
| 数字の出所 | 全ての数値に出所があるか |
| 先方の言葉との乖離 | ヒアリングで出た表現が使われているか |
| 勝ち筋のぶれ | 冒頭で立てた論点が最後まで通っているか |
| 提出物の欠落 | 名指しされた成果物が全て揃っているか |

## ルール

- 提案の勝ち筋そのものを否定する指摘は、**代案とセットでのみ**行う
- 好みの問題（言い回し、色）は P2 に留め、P0/P1 と混ぜない
- 全面書き直しの提案は最終手段。まず部分修正で解けないか検討する
- 「もっと具体的に」だけの指摘はしない。何をどう具体化するかまで書く
- 褒めるために指摘を減らさない。P0 を見逃すことが最大の不親切
