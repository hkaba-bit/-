# 提案の判断基準

## このスキルが解く問題

提案の失注は、たいてい「良い提案でなかった」からではなく、
**先方が求めたことに答えていなかった**か、**決裁者が承認できなかった**かのどちらか。

書いている本人はその2つに気づけない。自分の勝ち筋に集中しているほど見落とす。
このスキルは、書く前と出す前に同じ基準で照合するための道具。

## 提案の評価優先順位

この順で判断する。上ほど優先度が高い。

| # | 基準 | 具体的に見ること |
|---|---|---|
| 1 | RFP・要望への適合 | 名指しされた提出物・論点に全て答えているか |
| 2 | 決裁者が承認できるか | 決裁の壁（予算会議・役員・社長）を越える材料があるか |
| 3 | 論点の一貫性 | 先方が繰り返した言葉への答えが芯として通っているか |
| 4 | 具体性 | 「伴走します」ではなく、誰が何を何回やるかまで書いてあるか |
| 5 | 差別化 | 競合が言えないことを言えているか |
| 6 | 見た目 | 上5つが満たされて初めて意味を持つ |

**網羅は評価されない。** 全項目に薄く触れるより、勝ち筋1つに密度を集中する。

## 与件整理

提案を書く前に以下を確定させる。埋まらない項目は推測で埋めず、
「要確認」として明示し、先方への質問として残す。

| 項目 | 確認すること |
|---|---|
| 決裁の壁 | 誰が何を根拠に承認するか |
| 予算の状態 | 上限額／未計上／削減余地を求められているか |
| 先方が繰り返した言葉 | 議事録で2回以上出た不満・要望。**これが論点** |
| 提出物の指定 | RFPで名指しされた成果物 |
| 競合状況 | コンペか随意か。相手が何を出しそうか |
| 判断時期 | いつ何が決まるか |

**勝ち筋は1つに絞る。** 「予算も体制もSEOも心配」は論点ではない。
先方が最も繰り返した1つが論点。

## 書き方の規約

- 主語を曖昧にしない。「対応します」ではなく「弊社ディレクターが週1回」
- 効果は必ずレンジと前提条件つき。単一値の断定はしない
- 金額は税別・税込を明示し、初期費用と月額を混在させない
- 専門用語を使ったら、その場で1行の言い換えを添える
  （決裁者にマーケ理解があるとは限らない）
- 先方の言葉をそのまま使う。ヒアリングで出た表現を勝手に言い換えない
- 「御社の課題は〜」と決めつけない。「〜と伺いました」と出所を示す

## 数字の扱い

| やること | やらないこと |
|---|---|
| 出所を明記（ヒアリング／公開情報／自社実績） | 出所不明の業界平均 |
| 幅で示す | 断定的な単一値 |
| 仮置きは「仮」と明示 | 仮を実数のように見せる |
| 調査日を書く | 古い調査を現在形で書く |

**出所が言えない数字は載せない。**
効果予測を単一値で出すと、達成できなかったときに提案全体の信頼が崩れる。

## 競合・他社の扱い

- 他社を落とす表現は使わない。事実の並列に徹する
- 比較は誰が数えても同じになる指標で行う（ページ数、更新頻度など）
- 主観評価（デザインの良し悪し）を数値化しない
- 他社の提案成果物が手元にある場合、再描画は新設部分に限定し、
  提案書には「貴社ご提供の資料に基づき」と出所を明記する

## 禁止事項

- 実在しない実績・受賞歴・数値の記載
- 先方から提供された資料の無断転用
- 案件情報・見積金額・先方担当者名の外部共有

## 併用するスキル

| 作りたいもの | 使うスキル |
|---|---|
| クリッカブルワイヤーフレーム | `gg-wireframe` |
| 費用シミュレーター等の動く資料 | `gg-proposal-artifact` |
| 提案書（PPTX） | `pptx` |

このスキルは**判断基準**を提供する。上記スキルで作るときも、
評価優先順位と数字の扱いはこのスキルの規約に従う。
