# Claude だけで回す（依頼書 → ②Claude 子セッション → ③Claude 定期実行 → PR）

依頼書が `runner: claude` のときの経路。PC（Orca）も ChatGPT（Dots・Codex）も使わず、Claude Code on the web だけで依頼書を消化する。
分担の正本は `references/role-split.md`、Dots 経路は `references/dots-workflow.md`、PC 経路は `references/orca-workflow.md`。

---

## 1. 全体像

| 工程 | 担当 | 起動のしかた |
|---|---|---|
| ① 情報整理 → 依頼書 | Claude | 人間が頼む。`gg-handoff` で `runner: claude` の依頼書を main に入れる |
| 割り振り | 定期実行「gg パイプライン」 | **自動**。平日 9〜20 時の毎時7分。人間が「今すぐ回して」でも可 |
| ② 資料・ワイヤー作成 → PR | Claude Code（子セッション） | 定期実行が依頼書1件ごとに新しいセッションを立てる |
| ③ チェック・ブラッシュアップ | Claude Code（定期実行のセッション） | 同じ定期実行が、②とは別のセッションで行う |
| マージ | 人間（蒲） | GitHub |

② と ③ は別のセッションなので、「作った側に検品させない」（AGENTS.md 第4章）は守られる。

---

## 2. 状態の受け渡し

状態は GitHub と Claude のセッション一覧だけで判定する。ローカルの記録は持たない。

| 状態 | 見分け方 |
|---|---|
| 未着手 | main の依頼書が `status: ready` かつ `runner: claude`。`[handoff:<ファイル名>]` を含む open な PR が無く、タイトル `gg②: <ファイル名>` のセッションが直近3時間に無い |
| ② 作業中 | タイトル `gg②: <ファイル名>` のセッションがある（PR はまだ） |
| ③ 待ち／人間待ち／完了 | `references/dots-workflow.md` §2 と同じ（PR タイトルの `[handoff:…]` と記録コメント `<!-- gg-review sha=… -->`） |
| 止まっている | ② のセッションが失敗した、または3時間たっても PR が無い → §3 の手順 2-4 |

---

## 3. 定期実行「gg パイプライン」の手順

定期実行から起こされた Claude Code がやること。1回の起動で、割り振り → ③ の順に行う。

### 割り振り（②）
1. main を pull し、`node scripts/handoff-scan.mjs --list` で `Claude` と出る依頼書を集める
2. それぞれについて、`[handoff:<ファイル名から .md を除いたもの>]` を含む open な PR があれば飛ばす
3. `list_sessions` で、タイトルが `gg②: <ファイル名>` のセッションが直近3時間にあれば飛ばす（作業中）。3時間以上前のものしか無く PR も無ければ、失敗とみなして1回だけ立て直す。2回目も PR が無ければ、依頼書を `status: blocked` にする PR を作り、人間に知らせる
4. 残った依頼書ごとに `create_session` で子セッションを立てる（1回に最大3件、ファイル名の日付が古い順）
   - タイトル：`gg②: <ファイル名>`
   - リポジトリ：`https://github.com/hkaba-bit/-`（main）
   - 指示文：「AGENTS.md の第4章『Claude Code がクラウドで②を作るとき』に従い、依頼書 <依頼書のパス> を処理して PR を作ってください。依頼書の Context にある Skill を開いて作り、Done when を自分で確かめてから PR を出してください。PR のマージはしないでください。」

### ③
`references/dots-workflow.md` §5 の手順をそのまま行う（`[handoff:` を含む open な PR が対象。② が Claude でも Codex でも同じ）。

### 報告
- 子セッションを立てた、または PR を ③ 処理したときだけ、依頼書名・PR 番号・結果を1〜3行で報告する
- 何もなかった回は報告しない

## 4. 登録内容

| 項目 | 値 |
|---|---|
| 名前 | gg パイプライン |
| 頻度 | 平日 9〜20 時（日本時間）の毎時7分 |
| 起動 | リポジトリが入った既存のセッションに届ける（新規セッション方式はリポジトリを付ける操作が claude.ai の画面でしか無いため使わない） |
| 指示文 | 「`references/claude-pipeline.md` §3 の手順で、割り振り（②）と ③ を行う」 |

そのセッションをアーカイブすると届かなくなる。作り直すときは新しいセッションで定期実行を登録し直す。

---

## 5. やらないこと

| NG | なぜ |
|---|---|
| 定期実行のセッション自身で ② を作る | ③ と同じセッションになり、作った側が検品することになる |
| PR をマージする | マージは人間が決める |
| 1回に4件以上の子セッションを立てる | 費用と、③ が追いつかなくなるため |
